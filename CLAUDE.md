## What this project is

`mcpgen` (module path: `github.com/donaldgifford/mcp-go-gen`) is an HCL2-driven code generator that emits a complete, runnable Go MCP server from a declarative spec. Read `docs/adr/0001-mcpgen-architecture.md` and `docs/design/0004-mcpgen-generator.md` before making non-trivial changes — they are the source of truth for architectural decisions and are referenced from commit messages and reviews.

Key architectural constraints that shape all work here:

- **Two codegen technologies, deliberately.** `text/template` + `go/format.Source()` is used to write *new* files; `github.com/dave/dst` (Decorated Syntax Tree) is used to *edit* existing files (specifically, wiring changes to a user's `main.go` in embed mode). Do not use `go/ast` for writing — it loses comments and spacing. Do not use regex/string edits for structural changes. This split is a deliberate decision recorded in ADR-0001.
- **Two output modes:** `--mode new` scaffolds a fresh Go module; `--mode embed` writes into an existing module and performs a minimal DST edit at a required `// mcpgen:hook` marker. If the marker is absent, fail loudly — never guess.
- **Two proxy-input modes:** tools can be described inline in HCL or by reference to an OpenAPI 3.x document (via `github.com/pb33f/libopenapi`). Both paths converge on a common internal model before generation.
- **Generated files carry `// Code generated by mcpgen. DO NOT EDIT.`** and are expected to be regenerated. User-owned files are clearly separated. Regeneration must be idempotent — byte-identical output for the same spec.
- **Observability is on by default** (slog JSON, Prometheus `/metrics`, OTel tracing). Users opt out via HCL; the generator does not ship a mode where it is off by default.

Auth schemes the generator must support: none, static bearer, OIDC/JWT with fixed issuer/JWKS, dynamic OIDC discovery.

## Commands

This project uses a `make`-driven workflow. Tool versions are pinned in `mise.toml` (Go 1.26.1, golangci-lint 2.11.4, goreleaser, mockery, goimports, etc.) — use `mise install` if the toolchain isn't set up.

- `make build` — build the binary to `build/bin/mcp-go-gen` with version/commit ldflags baked in.
- `make test` — `go test -v -race ./...` across the module.
- `make test-pkg PKG=./path/to/pkg` — run a single package's tests.
- `make test-coverage` — produces `coverage.out` (consumed by CI and codecov).
- `make test-report` — coverage + opens the HTML report.
- `make lint` / `make lint-fix` — golangci-lint (config at `.golangci.yml`, Uber-style preset with errcheck/errorlint/staticcheck/gocyclo/funlen/contextcheck/bodyclose and more).
- `make fmt` — `gofmt -s -w` plus `goimports -local github.com/donaldgifford`. Run this before committing.
- `make check` — pre-commit shortcut (`lint` + `test`).
- `make ci` — full CI pipeline locally (`lint` + `test` + `build` + `license-check`).
- `make license-check` — `go-licenses` check against the allowed list (Apache-2.0, MIT, BSD-2/3, ISC, MPL-2.0).
- `make release-check` / `make release-local` — validate and snapshot-build via goreleaser without publishing.

Running a single Go test within a package: `go test -v -race -run TestName ./path/to/pkg`.

**Known inconsistencies in the scaffold** (worth fixing when touched, but don't go out of your way):
- `.goreleaser.yml` still references `./cmd/forge` and a binary named `forge` — it was copied from another project and needs updating to `./cmd/mcp-go-gen` before a real release.
- The `make run` target points at `./build/bin/repo-guardian` — same template-leftover issue.

## Repo layout

- `cmd/mcp-go-gen/` — binary entry point; only owns `main.main()` and the `version`/`commit` ldflag variables. All real work lives under `internal/`.
- `internal/cli/` — Cobra command tree (`root`, `init`, `validate`, `generate`), slog logger wiring, and the `ErrNotImplemented` sentinel for stubbed subcommands. Subcommands retrieve the logger via `loggerFrom(cmd.Context())`.
- `internal/config/`, `internal/ir/`, `internal/gen/`, `internal/openapi/`, `internal/dst/`, `internal/scaffold/` — placeholder packages with `doc.go`; implementations land in the phase called out in each file's comment.
- `docs/` — managed by [docz](https://github.com/donaldgifford/docz). Subdirs: `adr/`, `rfc/`, `design/`, `impl/`, `plan/`, `investigation/`. Each has a `README.md` index that is regenerated automatically. Configuration in `.docz.yaml`. Don't edit the index tables by hand — use `docz update` (or the `docz:update` skill).
- `docs/building-mcpgen.md` / `docs/using-mcpgen.md` — long-form walkthroughs that predate the docz structure; they are canonical reference material for the HCL schema, template shape, DST edit strategy, and generated layout.
- `.github/workflows/` — CI (lint, test, build, security scan with govulncheck + Trivy, docker bake), license check, PR labeler, release.
- `.claude/settings.json` — enables a specific set of Claude Code plugins (`go-development`, `docz`, `makefiles`, `mise`, `shell-scripting`, `claude-md`, `systems-programming`, `docker`, `skill-creator`, `ralph-loop`, `gopls-lsp`). These skills are expected to be available.

## Documentation workflow

Architectural decisions go in `docs/adr/`, detailed designs in `docs/design/`, proposals in `docs/rfc/`, implementation tracking in `docs/impl/`, general plans in `docs/plan/`, open questions in `docs/investigation/`. Use the `docz` CLI (or the `docz:create` skill) to create new documents — it assigns IDs, fills frontmatter, and updates the index. Status values per type are enumerated in `.docz.yaml`.

When making an architectural change, update or supersede the relevant ADR; don't just change code silently. DESIGN-0004 and ADR-0001 are tightly coupled — changes to one typically require a note in the other.

## Style

- golangci-lint config follows Uber's Go Style Guide. Notable knobs: errors wrapped with `%w`, preallocated slices where size is known, contexts propagated on HTTP calls, response bodies closed, constants for repeated strings, bounded cyclomatic/cognitive complexity, no naked returns.
- `goimports -local github.com/donaldgifford` — local imports grouped separately.
- Commit message convention drives release notes (goreleaser groups by `^feat:` / `^fix:`; `^docs:` / `^test:` / `^chore:` are excluded from changelogs). Use conventional-commit-style prefixes.
- Branch naming feeds the PR labeler (`.github/labeler.yml`): `feat/`, `fix/`, `chore/`, `docs/`, `bug/`.
