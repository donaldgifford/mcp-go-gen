## What this project is

`mcpgen` (module path: `github.com/donaldgifford/mcp-go-gen`) is an HCL2-driven code generator that emits a complete, runnable Go MCP server from a declarative spec. Read `docs/adr/0001-mcpgen-architecture.md` and `docs/design/0004-mcpgen-generator.md` before making non-trivial changes — they are the source of truth for architectural decisions and are referenced from commit messages and reviews.

Key architectural constraints that shape all work here:

- **Two codegen technologies, deliberately.** `text/template` + `go/format.Source()` is used to write *new* files; `github.com/dave/dst` (Decorated Syntax Tree) is used to *edit* existing files (specifically, wiring changes to a user's `main.go` in embed mode). Do not use `go/ast` for writing — it loses comments and spacing. Do not use regex/string edits for structural changes. This split is a deliberate decision recorded in ADR-0001.
- **Two output modes:** `--mode new` scaffolds a fresh Go module; `--mode embed` writes into an existing module and performs a minimal DST edit at a required `// mcpgen:hook` marker. If the marker is absent, fail loudly — never guess.
- **Two proxy-input modes:** tools can be described inline in HCL or by reference to an OpenAPI 3.x document (via `github.com/pb33f/libopenapi`). Both paths converge on a common internal model before generation.
- **Generated files carry `// Code generated by mcpgen. DO NOT EDIT.`** and are expected to be regenerated. User-owned files are clearly separated. Regeneration must be idempotent — byte-identical output for the same spec.
- **Observability is on by default** (slog JSON, Prometheus `/metrics`, OTel tracing). Users opt out via HCL; the generator does not ship a mode where it is off by default.

Auth schemes the generator must support: none, static bearer, OIDC/JWT with fixed issuer/JWKS, dynamic OIDC discovery.

## Commands

This project uses a `make`-driven workflow. Tool versions are pinned in `mise.toml` (Go 1.26.1, golangci-lint 2.11.4, goreleaser, mockery, goimports, etc.) — use `mise install` if the toolchain isn't set up.

- `make build` — build the binary to `build/bin/mcp-go-gen` with version/commit ldflags baked in.
- `make test` — `go test -v -race ./...` across the module.
- `make test-pkg PKG=./path/to/pkg` — run a single package's tests.
- `make test-coverage` — produces `coverage.out` (consumed by CI and codecov).
- `make test-report` — coverage + opens the HTML report.
- `make lint` / `make lint-fix` — golangci-lint (config at `.golangci.yml`, Uber-style preset with errcheck/errorlint/staticcheck/gocyclo/funlen/contextcheck/bodyclose and more).
- `make fmt` — `gofmt -s -w` plus `goimports -local github.com/donaldgifford`. Run this before committing.
- `make check` — pre-commit shortcut (`lint` + `test`).
- `make ci` — full CI pipeline locally (`lint` + `test` + `build` + `license-check`).
- `make license-check` — `go-licenses` check against the allowed list (Apache-2.0, MIT, BSD-2/3, ISC, MPL-2.0).
- `make release-check` / `make release-local` — validate and snapshot-build via goreleaser without publishing.
- `make demo-up` / `make demo-up-oidc` — bring up the IMPL-0002 Compose stack (3 services bearer / 4 services with `demo-idp`). Refuses if `demo/.env` is missing.
- `make demo-down` / `make demo-logs` / `make demo-rebuild` / `make demo-clean` — tear down (with volume cleanup), tail logs, restart, blow away regenerated tree.
- `make demo-test` — run the demo's separate-module Go tests (`demo/api/` and `demo/idp/`); CI's `make ci` deliberately doesn't descend there per IMPL-0002 Resolved OQ #3.
- `make demo-mint-service-token` / `make demo-mint-user-token` — curl `demo-idp/token` and print a JWT for `.env` paste / inspector paste respectively (Phase 5 only).

Running a single Go test within a package: `go test -v -race -run TestName ./path/to/pkg`.

The repo was originally bootstrapped from another scaffold; treat any unfamiliar binary name, image name, bake target, or directory in CI/release config as suspect until verified. Two such leftovers (goreleaser cmd path, `make run` binary) were fixed pre-v0.0.1; two more (missing `release` bake target, malformed `images:` value) only surfaced post-merge when the v0.0.1 Docker job ran. `make release-check` does not validate workflow YAML or `docker-bake.hcl`, so green local checks are not sufficient — when touching `.goreleaser.yml`, `docker-bake.hcl`, `.github/workflows/release.yml`, or `.github/dependabot.yml`, audit for stale references.

## Release pipeline

`.github/workflows/release.yml` runs three jobs in series on every push to `main`:

1. **bump-version** uses `jefflinse/pr-semver-bump` with `noop-labels: "dont-release"`. The PR labeler (`.github/labeler.yml` + `.github/workflows/pr-labels.yml`) requires every PR to carry one of `major | minor | patch | dont-release`; the `dont-release` label is the opt-out for infra/CI-only changes that must not bump a version. When skipped, `outputs.skipped == 'true'`.
2. **release** is gated on `needs.bump-version.outputs.skipped != 'true'` and runs goreleaser with GPG signing (`GPG_PRIVATE_KEY`, `GPG_FINGERPRINT` repo secrets are required — without them the GPG import step fails and the release job aborts before goreleaser runs).
3. **docker** is gated the same way and uses `docker/bake-action` with `targets: release` against `docker-bake.hcl`.

`docker-bake.hcl` defines two targets:

- `ci` — used by `.github/workflows/ci.yml` for sanity multi-arch builds with hardcoded tags.
- `release` — multi-arch with `output = ["type=registry"]` so it pushes. **It inherits from a separate `docker-metadata-action` target which is intentionally empty.** That name is the default target `docker/metadata-action` injects tags/labels into via its `bake-file-tags` / `bake-file-labels` outputs; the inheritance is what wires the workflow's metadata-action result into the release build. Don't rename either target without also updating `release.yml`.

The `metadata-action` `images:` input must be the full image name (`ghcr.io/donaldgifford/mcp-go-gen`). A trailing slash with no name renders broken tags like `ghcr.io/donaldgifford/:0.0.1` and bake fails late.

## Repo layout

- `cmd/mcp-go-gen/` — binary entry point; only owns `main.main()` and the `version`/`commit` ldflag variables. All real work lives under `internal/`.
- `internal/cli/` — Cobra command tree (`root`, `init`, `validate`, `generate`), slog logger wiring, and the `ErrNotImplemented` sentinel for stubbed subcommands. Subcommands retrieve the logger via `loggerFrom(cmd.Context())`.
- `internal/config/` — HCL2 schema (`schema.go`), decoder (`decode.go`), and the `ToIR` converter with every cross-field validation rule (`convert.go`). Fixtures under `testdata/hcl/{good,bad}/*.hcl`; `FuzzHCLDecode` lives in `fuzz_test.go`.
- `internal/ir/` — the immutable spec the template renderer consumes. `Spec`, `Server`, `Observability`, `ProxySpec`, `EmbedSpec`, `Tool`, `Field`, `HTTPBackend`; `AuthSpec` is a sealed sum type with `AuthNone|Bearer|OIDC|OIDCDynamic`.
- `internal/gen/` — template-driven codegen pipeline. `plans.go:BuildPlans` is the single source of truth for the file set; `render.go:Render` runs templates into in-memory buffers, applies `go/format.Source` to `GoFormat` plans, then commits via `Writer.Commit` atomically. `writer.go` has `FSWriter` (empty-unless-`--force`) and `DryRunWriter` (sorted `<path> (<bytes>)` lines). Templates live under `internal/gen/templates/**` and are embedded via `//go:embed`.
- `internal/scaffold/tidy.go` — shells out to `go mod tidy` after generate; fails loudly when `go` is missing from PATH (resolved-Q #5 in IMPL-0001).
- `internal/openapi/` — wraps `github.com/pb33f/libopenapi`. `Load(path)` rejects Swagger 2.0 and remote `$ref` entries up front, then builds the v3 model. `(*Doc).Operation(id)` scans every method on every PathItem and returns the first match flattened into `{Method, Path, Summary, Parameters[]}`. Type mapping lives in `resolveSchema`; nested `object` parameters short-circuit here with the canonical rejection message. `config.ToIR` consumes these via `applyOpenAPIMerge` in `internal/config/convert.go`.
- `internal/dst/` — wraps `github.com/dave/dst` + `dst/decorator` for structural edits to user Go source. `Edit(src, pkgPath, pkgAlias)` locates the `// mcpgen:hook` marker inside `func main`, inserts an `if err := <alias>.Register(ctx, app, cfg); err != nil { log.Fatalf(...) }` block after it, and adds the import — idempotently. Structural AST compare (`hasRegisterCall`) drives the "already embedded" no-op path; `EditResult.Changed` tells the caller whether to rewrite the file.
- `internal/scaffold/modpath.go:ModulePath` walks upward from `--out` looking for `go.mod` and returns the declared module path. Embed mode uses this to wire the correct import paths through `ir.Spec.ModulePath`.
- `demo/` — IMPL-0002 demo harness, three separate Go modules (intentionally — see Resolved OQ #3) that don't bleed into the generator's go.mod / govulncheck / Trivy. `demo/api/` is a hand-written HTTP service with three auth trees (`/api/noauth`, `/api/bearer`, `/api/oauth2flow`); `demo/idp/` is the Phase 5 OIDC issuer (per INV-0001, hand-rolled RS256 JWKS issuer chosen over dex/Keycloak); `demo/mcp-server/` is the regenerated MCP server (gitignored). Two parallel HCL specs drive it: `demo/mcpgen.hcl` (bearer flow, eight tools) and `demo/mcpgen-oidc.hcl` (OIDC flow, four tools). `demo/compose.yaml` wires three or four services on a user-defined bridge; `mcp-inspector` listens on `:6274`, `demo-idp` publishes `:5556` so the host can `curl /token`.

## Renderer conventions

- `BuildPlans(spec)` is deterministic — same `*ir.Spec`, same ordered plan list. Idempotency of the generated tree depends on this.
- Templates use a small funcMap (`goIdent`, `snake`, `joinPath`, `quotedOr`). Nested ranges bind outer-loop vars (`{{range $tool := .Tools}}`) so inner ranges can still reach the spec.
- Every generated `.go` file starts with `// Code generated by mcp-go-gen. DO NOT EDIT.` before `go/format.Source` runs. If formatting fails, the unformatted buffer is included in the error for direct debugging.
- The current template set covers: `go.mod`, `Makefile`, `Dockerfile`, `cmd/<server>/main.go`, `internal/observability/{logging,metrics,tracing}.go`, `internal/mcpserver/{server,tools}.go`, plus `internal/mcpserver/backend.go` when `spec.Proxy != nil`. `internal/mcpauth/auth.go` is rendered from one of four templates (`auth_none`, `auth_bearer`, `auth_oidc`, `auth_oidc_dynamic`) selected by `authTemplate(spec.Auth)` in `internal/gen/plans.go`. All four export an identical API (`Subject`, `SubjectFromContext`, `ContextWithSubject`, `NewMiddleware(ctx)`, `(*Middleware).Wrap`, `OnFailure func(reason string)`) so `cmd/main.go.tmpl` never forks on auth.
- In `--mode embed`, `gen.BuildPlansEmbed(spec, overwriteStubs)` filters the full plan down to the `internal/` subset (no `go.mod`, `Makefile`, `Dockerfile`, or `cmd/<server.name>/*`). Import paths in every template reference `{{.ModulePath}}/internal/...`; ToIR populates `ModulePath` with `server.name` by default, and the embed CLI overwrites it with the user's `go.mod` path before rendering.
- `go.mod.tmpl` adds `github.com/coreos/go-oidc/v3` only when `authKind` resolves to `oidc` or `oidc_dynamic`; `go mod tidy` reconciles `go.sum` after render. This keeps bearer/none binaries free of the OIDC transitive closure.
- The generator emits a stderr warning when `auth { none {} }` is selected. The rendered file also carries a `// WARNING` banner so the choice is visible in the generated tree, not just at generate time.
- Tracing imports are conditional on `.Observability.Tracing.Enabled` to keep the noop-mode binary free of the OTLP SDK. This deviates from resolved-Q #10's "always import" wording but keeps `go vet`/`goimports` happy; the noop mode still goes through the same `InitTracing` shape and `noop.NewTracerProvider()`.
- Metrics listener has two shapes controlled at runtime by `metrics.addr`: empty → shared mux on the MCP listener; non-empty → second `http.Server` in its own goroutine with matched shutdown. Both live in the same template.
- The CLI copies the source `mcpgen.hcl` verbatim into the output root after render (before `go mod tidy`) so regeneration from the generated tree is self-contained.
- Tool handlers in `tools.go.tmpl` branch on whether `tool.Backend` is non-nil. Tools without a backend keep the `"<tool>: ok"` stub (used by `--mode embed` to delegate to the user's `service_stubs.go`). Tools with a backend split inside the same handler: the URL build + Do/read/switch are shared; only the request constructor varies between GET (`http.NewRequestWithContext(ctx, "GET", u.String(), nil)`) and POST/PUT/PATCH (`bytes.NewReader(bodyBytes)` plus `Content-Type: application/json`). The `bytes` import is gated on `Spec.HasBodyTools()` so GET-only proxies don't trip `go vet`; `encoding/json` is unconditional on `.Proxy` because the structured-or-text response helper uses it on every tool.
- Path-param substitution lives at runtime in `(*Backend).SubstitutePath(template, params)` — the per-tool generated handler emits `pathParams := map[string]string{...}` and a single `t.Backend.SubstitutePath(...)` call instead of an inline `strings.NewReplacer` literal. Tools without path params skip the map allocation entirely. Centralizing the helper makes future extensions (validation, custom escaping, slash handling) a one-file change.
- The 2xx success path returns through a generated `toolResultFromBody(body []byte) *mcp.CallToolResult` helper (gated on `.Proxy`) that tries `json.Unmarshal` and uses `mcp.NewToolResultStructured(parsed, string(body))` when it succeeds, falling back to `mcp.NewToolResultText(string(body))` for non-JSON responses. MCP clients that understand structured content render JSON tool output richly; older clients see the text fallback. Replaces the prior unconditional `NewToolResultText` per IMPL-0002 Resolved OQ #1.
- Optional input fields (`required = false`) read through `req.GetString(key, "")` rather than the unconditional `RequireString` used for required fields. For body marshaling, the renderer emits a `map[string]any` populated via `req.GetArguments()` presence checks so optional fields land in the body only when the user supplied them — this lets the upstream API distinguish "field absent" from "field set to empty string" via the standard JSON convention.

## Decoder and IR conventions

- The decoder returns `*Config, hcl.Diagnostics` — callers check `diags.HasErrors()` before using the config. Structural errors (missing required attribute, wrong type) surface here.
- Semantic rules (exactly-one auth block, unique tool names, openapi_operation requiring proxy.openapi.spec, field-type validation, version equality, duration parsing) live in `config.ToIR`, which returns a standard `error` via `errors.Join` so one invocation surfaces every violation at once.
- Observability defaults are applied during `ToIR`, not in the HCL decoder. The resulting `ir.Observability` always has concrete values; templates never branch on "was the block present?"
- `AuthSpec` is sealed via an unexported `isAuthSpec()` method. Do not add new variants outside `internal/ir/auth.go` — the generator relies on the closed set to avoid fallthrough bugs.
- New field types (beyond the v1 primitives + flat arrays + enum) are explicitly out of scope for v1 per DESIGN-0004 non-goals. Rejection messages in `parseFieldType` cite this rule with a "v1 allows" hint.
- OpenAPI-backed tools: `openapi_operation = "<id>"` on a tool block defers parameter + HTTP shape to the spec. The tool's HCL `input` block is forbidden when `openapi_operation` is set — parameters come from the spec, not the HCL. Tool `description` is `,optional` because the spec's operation summary can fill in; ToIR rejects tools that end up with no description from either source. Relative `proxy.openapi.spec` paths resolve against the HCL file's directory (`config.Decode`).

## Gotchas worth knowing

- HCL2 syntax requires nested blocks on separate lines. `auth { none {} }` on a single line is rejected with "A single-line block definition can contain only a single argument." Fixtures and `init`-emitted starters use multi-line block form throughout.
- `gohcl` treats `hcl:"-"` as a required attribute literally named `-`. To carry non-HCL state on a Config struct, post-process the decoded value in `config.Decode` (see `resolveRelative` for the proxy.openapi.spec path-resolution pattern) — don't add a struct tag-skipped field.
- Conditional template imports must gate on the same `{{if}}` predicate as their use sites, otherwise `go/format` rejects the rendered file with `imported and not used`. Examples: `internal/mcpserver/backend.go.tmpl` gates `os` on `.Proxy.Bearer`; `internal/observability/tracing.go.tmpl` gates the OTLP SDK packages on `.Observability.Tracing.Enabled` (with the noop branch importing `trace/noop` instead).
- The bearer-auth template's `tokens_env` parses as `<subject1>:<token1>,<subject2>:<token2>,...` — a bare token without the `subject:` prefix is silently dropped (the parser produces an empty token→subject map and every request 401s). The MCP_BOUNDARY_TOKEN default in `demo/.env.example` is therefore `demo-user:mcp-boundary-secret-please-change`, not the bare secret. Inspector users paste only the token portion (after the colon) into the `Authorization: Bearer …` custom header.
- MCP Inspector v0.21+ binds to `127.0.0.1` inside its container by default, so Docker's host port forward has nothing on the bridge interface to talk to and TCP connects then resets. `demo/compose.yaml` sets `HOST=0.0.0.0` and publishes BOTH `:6274` (React UI) and `:6277` (proxy backend the UI calls into). It also sets `DANGEROUSLY_OMIT_AUTH=true` so users don't have to copy a 64-char proxy session token from the container logs on every restart — acceptable for a local demo, not for anything else.
- The Inspector's "Custom Headers" panel sends header values verbatim (no `Bearer ` auto-prepending) and is the right place to authenticate to the MCP boundary. The "Configuration" panel above it is for the proxy session token (disabled by `DANGEROUSLY_OMIT_AUTH`). When the boundary header is missing/wrong, demo-mcp returns 401 and the Inspector then escalates to OAuth-discovery, which 404s with a misleading `OAuth Authentication Failed: HTTP 404 / Invalid OAuth error response` dialog. The `demo/README.md` quickstart carries a `> [!WARNING]` callout pointing at the `Bearer ` prefix and the subject:token format because both bit users during dogfooding.
- `docs/` — managed by [docz](https://github.com/donaldgifford/docz). Subdirs: `adr/`, `rfc/`, `design/`, `impl/`, `plan/`, `investigation/`. Each has a `README.md` index that is regenerated automatically. Configuration in `.docz.yaml`. Don't edit the index tables by hand — use `docz update` (or the `docz:update` skill).
- `docs/building-mcpgen.md` / `docs/using-mcpgen.md` — long-form walkthroughs that predate the docz structure; they are canonical reference material for the HCL schema, template shape, DST edit strategy, and generated layout.
- `.github/workflows/` — CI (lint, test, build, security scan with govulncheck + Trivy, docker bake), license check, PR labeler, release.
- `.claude/settings.json` — enables a specific set of Claude Code plugins (`go-development`, `docz`, `makefiles`, `mise`, `shell-scripting`, `claude-md`, `systems-programming`, `docker`, `skill-creator`, `ralph-loop`, `gopls-lsp`). These skills are expected to be available.

## Documentation workflow

Architectural decisions go in `docs/adr/`, detailed designs in `docs/design/`, proposals in `docs/rfc/`, implementation tracking in `docs/impl/`, general plans in `docs/plan/`, open questions in `docs/investigation/`. Use the `docz` CLI (or the `docz:create` skill) to create new documents — it assigns IDs, fills frontmatter, and updates the index. Status values per type are enumerated in `.docz.yaml`.

When making an architectural change, update or supersede the relevant ADR; don't just change code silently. DESIGN-0004 and ADR-0001 are tightly coupled — changes to one typically require a note in the other.

## Style

- golangci-lint config follows Uber's Go Style Guide. Notable knobs: errors wrapped with `%w`, preallocated slices where size is known, contexts propagated on HTTP calls, response bodies closed, constants for repeated strings, bounded cyclomatic/cognitive complexity, no naked returns.
- `goimports -local github.com/donaldgifford` — local imports grouped separately.
- Commit message convention drives release notes (goreleaser groups by `^feat:` / `^fix:`; `^docs:` / `^test:` / `^chore:` are excluded from changelogs). Use conventional-commit-style prefixes.
- Branch naming feeds the PR labeler (`.github/labeler.yml`): `feat/`, `fix/`, `chore/`, `docs/`, `bug/`.
